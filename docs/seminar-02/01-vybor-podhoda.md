# Сравнение подходов и выбор

Продукт: NeuroGateway. Сейчас идёт спринт 0 «Фундамент» (21.09.2026–05.10.2026). В бэклоге уже лежат эпики E00–E17, от регламента команды до GA. контракт публичного API ещё не зафиксирован.

## Waterfall

Сначала полное описание агрегатора, потом разработка, потом проверка в конце. Для NeuroGateway это плохо стыкуется с фактом: фазы MVP, Beta и GA уже названы, но состав MVP зависит от конкурентного анализа и PRD, которые ещё в работе. Ошибка в схеме биллинга или в контракте `POST /v1/chat/completions` всплыла бы после того, как под неё написаны адаптеры.

## Scrum

Работа отрезками по две недели: план, ежедневная сверка, демо, ретро. Незакрытое переносится. Это совпадает с тем, как в «Сфере» уже заведён спринт 0 и как задачи связаны блокировками: схему LLM нельзя обгонять спецификацией API, спецификацию нельзя обгонять каркасом gateway.

Жёсткий Scrum без доски внутри спринта здесь слабый. Четыре человека совмещают проект с остальной учёбой, и обещание «закроем весь объём к пятнице» регулярно расходится с фактом.

## Kanban

Непрерывный поток и лимит незавершённой работы. Подходит к тому, что требования приезжают по эпикам, а не одним ТЗ. Сам по себе не задаёт дату демо и не решает, какой набор блокирующих задач обязан войти в ближайшие две недели. У агрегатора такие узлы есть: без канонической схемы запроса нельзя честно принять ни адаптер, ни биллинг.

## Выбор

Гибрид: **двухнедельный Scrum, внутри спринта доска с лимитом**.

1. Спринт уже единица планирования в «Сфере», а выход фаз (MVP, Beta, GA) привязан к демо.
2. Задачи фундамента блокируют друг друга. Состав спринта нужно собирать явно, а не вытягивать первую свободную карточку.
3. Внутри двух недель загрузка видна только по колонкам. Лимит — не больше двух задач в работе на человека, иначе схема, OpenAPI и ADR одновременно числятся начатыми и не двигаются.
