# ID24_API-84 · E06-02: health-трекинг провайдеров и эндпоинтов

Код: [routing/health.go](../../routing/health.go), [routing/endpoint.go](../../routing/endpoint.go), тесты: [routing/health_test.go](../../routing/health_test.go).

Каждый вызов эндпоинта записывается в посекундную корзину: число запросов, ошибки, задержки, TTFT, выходные токены. По корзинам считаются окна 1, 5 и 30 минут: доля ошибок, p50 задержки, средний TTFT, токены в секунду. Корзины старше 30 минут удаляются.

| Статус | Условие (по умолчанию, `DefaultThresholds`) |
|---|---|
| `down` | 3 ошибки подряд или ≥ 50% ошибок за минуту при ≥ 5 запросах |
| `degraded` | ≥ 10% ошибок за 5 минут при ≥ 5 запросах или p50 задержки за 5 минут > 10 с |
| `up` | всё остальное |

Успешный вызов обнуляет счётчик ошибок подряд, поэтому после восстановления эндпоинт возвращается в `up`, как только ошибки выходят из окна.

Между подами: `Snapshot` отдаёт посекундные корзины эндпоинта, `Merge` складывает их с локальными. Статус считается по общим данным. `Statuses()` отдаёт снимок для метрик, статус-страницы и каталога моделей.

`Endpoint` и `Registry` — минимальная модель «модель → эндпоинты» для маршрутизации: приоритет, вес, ручное отключение. Полная сущность (цена, контекст, параметры, политика данных, админка) — это ID24_API-83.

## Критерий приёмки

`TestMockFailureTurnsDownWithin30Seconds`: mock-провайдер две минуты отвечает успешно, затем ломается. При запросе раз в секунду эндпоинт переходит в `down` через **3 с** (порог — 30 с).

```sh
go test ./routing/ -run Health -v
go test ./routing/ -v
```

## Ограничения

Транспорт снимков между подами (публикация `Snapshot` в Redis по таймеру) и экспорт `Statuses()` в Prometheus появятся вместе с HTTP-сервером шлюза (ID24_API-47) и observability (ID24_API-38). Сервера пока нет.
