# ID24_API-204 · R09: баланс и hold при ошибке генерации

Код: [gateway/billing.py](../../gateway/billing.py), тесты: [tests/test_hold_r09.py](../../tests/test_hold_r09.py).

| Исход вызова провайдера | Что делает ledger | Ответ |
|---|---|---|
| Успех, факт не больше резерва | capture факта, разница возвращается в кошелёк | 200 |
| Успех, факт больше резерва | hold остаётся, генерация в `to_reconcile` | 200, `reconcile: true` |
| Подтверждённый отказ (любое исключение) | release, баланс как до запроса | 502, `released: true` |
| `ProviderOutcomeUnknown` (обрыв после отправки) | hold остаётся, генерация в `to_reconcile`, TTL его не снимает | 504, `reconcile: true` |
| Повтор, пока hold не закрыт | провайдер не вызывается | 409 |
| Отрицательная, нецелая или bool-сумма | состояние не меняется, провайдер не вызывается | 400 |

Сверка закрывает генерацию через `Ledger.settle`: `None` — провайдер запрос не выполнил, hold освобождается; сумма — capture в пределах резерва. Повторный `settle` второй проводки не создаёт.

`authorize` возвращает `False`, если генерация уже известна. Поэтому 20 параллельных повторов одной генерации вызывают провайдера один раз и создают одну проводку capture.

Проверка:

```sh
python3 -m unittest discover -v   # 30 тестов, все успешно
```

Ограничение: ledger по-прежнему в памяти процесса. Устойчивость к рестарту и транзакционная идемпотентность в PostgreSQL относятся к ID24_API-205.
