# ID24_API-85 · E06-03: circuit breaker и ретраи с backoff

Код: [routing/breaker.go](../../routing/breaker.go), [routing/retry.go](../../routing/retry.go), [routing/router.go](../../routing/router.go), тесты: [routing/router_test.go](../../routing/router_test.go).

## Circuit breaker на эндпоинт

`closed → open`: 5 ошибок провайдера подряд или ≥ 50% ошибок среди последних 20 вызовов (не меньше 10). `open` держится 30 с, затем `half-open` пропускает один пробный вызов: успех замыкает breaker, ошибка снова размыкает. Ошибки клиента (`invalid_request`, `moderation`, `context_length_exceeded`) провайдера не ломают и breaker не трогают. Отмена запроса клиентом освобождает пробный слот без итога.

## Ретраи

- Повторяются только ошибки с `apierr.Error.Retryable()`: `provider_error` (5xx), `timeout`, `rate_limit` с `limit_source = provider`.
- Ошибка, обёрнутая в `routing.ErrAfterFirstByte` (клиент уже получил часть стрима), не повторяется.
- До 3 попыток на запрос, включая первую. Задержка — полный джиттер: случайная в `[0, min(2 с, 100 мс · 2^n))`.
- Повтор идёт на следующий эндпоинт модели. Порядок: up → degraded → down, внутри — приоритет реестра. Эндпоинты с разомкнутым breaker пропускаются. Эндпоинт после cooldown или долго простаивающий в down встаёт на своё место по приоритету и получает пробу, поэтому после восстановления возвращает себе трафик.

## Бюджет ретраев

Общий на шлюз, по схеме retry throttling из gRPC: 10 токенов, ошибка провайдера тратит 1, успех возвращает 0,1; ретраи разрешены, пока токенов больше 5. При массовом отказе 100 запросов дают не больше 110 вызовов провайдера вместо 300.

## Критерий приёмки

`TestChaosHalfErrorsWithSecondEndpointNoClientErrors`: у основного эндпоинта 50% ошибок 500, второй здоров. **2000 запросов, 0 ошибок у клиента.** Основной размыкается, раз в 30 с получает пробу и остаётся под наблюдением. `TestChaosWithoutBreakerStillNoClientErrors` — то же при отключённом breaker, только на ретраях: 1000 запросов без ошибок.

```sh
go test ./routing/ -v
go test -race ./routing/
```

Цепочка попыток (`[]Attempt`: модель, эндпоинт, провайдер, код, причина, задержка) возвращается вызывающему для логов. Её использует fallback (ID24_API-86).

Ограничение: chaos-тест выполняется в процессе на mock-провайдере. Прогон через сеть с инъекцией отказов относится к ID24_API-183, когда появится HTTP-сервер шлюза.
