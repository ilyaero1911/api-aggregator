# Сценарии и функциональные требования

Основание: контекст семинара 3 и персоны из `ID24_API-7`. Ниже семь сценариев, без которых нет первого среза. Идентификаторы стабильные: новое требование получает следующий номер, старый номер не переиспользуется.

| ID | Сценарий | Персона |
|---|---|---|
| US-01 | Зарегистрироваться и войти по email | Разработчик |
| US-02 | Выпустить API-ключ и увидеть его один раз | Разработчик |
| US-03 | Пополнить баланс заглушкой | Разработчик |
| US-04 | Получить ответ модели одним контрактом | Разработчик, стартап |
| US-05 | Не уйти в минус при пустом балансе | Команда, клиент |
| US-06 | Увидеть расход генерации без текста промпта | Разработчик, data-инженер |
| US-07 | Сменить модель тем же клиентским кодом | Стартап |

## Функциональные требования

| ID | Требование | Сценарий | Задача бэклога |
|---|---|---|---|
| FR-01 | Система создаёт учётную запись по email и паролю и пускает в кабинет только после успешного входа | US-01 | ID24_API-110 |
| FR-02 | Система выпускает ключ, показывает секрет один раз и дальше принимает только предъявление секрета, не его чтение из кабинета | US-02 | ID24_API-114 |
| FR-03 | На MVP операция «пополнить» увеличивает баланс на введённую сумму в рублях без вызова эквайринга и пишет проводку | US-03 | ID24_API-98 |
| FR-04 | `POST /v1/chat/completions` без стрима принимает канонический запрос и возвращает ответ выбранной модели | US-04 | ID24_API-49, ID24_API-24 |
| FR-05 | Перед вызовом провайдера система создаёт hold на оценку стоимости. Если доступного баланса не хватает, провайдер не вызывается, клиент получает отказ с кодом недостатка средств | US-05 | ID24_API-95 |
| FR-06 | После ответа система пишет списание по фактическим токенам и снимает hold. Повтор той же генерации не создаёт второе списание | US-04 | ID24_API-93, ID24_API-182 |
| FR-07 | Журнал показывает модель, провайдера, токены, задержку и сумму. Текст запроса и ответа в этой записи отсутствует | US-06 | ID24_API-131 |
| FR-08 | Запрос с другим именем модели из каталога проходит тем же методом и тем же ключом | US-07 | ID24_API-51, ID24_API-54 |

Требования Beta и GA (реальный эквайринг, организации, SSE, fallback между провайдерами) в этот список не входят. Они остаются в эпиках E06, E07, E08 и попадут в следующую версию требований отдельной записью журнала.
