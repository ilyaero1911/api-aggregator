# Истории и критерии приёмки

Истории ниже соответствуют FR-01…FR-08. Приёмка проверяется сценарием, а не оценкой «работает нормально».

## US-04. Ответ модели

Как разработчик, я хочу отправить один chat-запрос с ключом шлюза и получить текст модели, чтобы не подключать SDK провайдера.

Критерии:

- дан действующий ключ, модель из каталога и баланс, покрывающий оценку;
- когда клиент вызывает `POST /v1/chat/completions` без стрима;
- тогда статус 200, в теле есть текст ответа, в заголовках есть `X-Request-Id` и `X-Generation-Id`, в ledger одна проводка списания на фактические токены.

### Given / When / Then

**Given** ключ `k1`, модель `demo` привязана к mock-провайдеру, баланс 100 рублей, оценка запроса 2 рубля, mock отвечает 20 токенами ответа  
**When** клиент отправляет `POST /v1/chat/completions` с этим ключом и моделью `demo`  
**Then** статус 200, тело содержит текст mock, hold снят, списание одно, повторная доставка того же id генерации не создаёт вторую проводку

## US-05. Пустой баланс

Как владелец баланса, я хочу, чтобы запрос без денег не дошёл до провайдера, чтобы не получить долг.

**Given** ключ `k1` и доступный баланс 0  
**When** клиент отправляет тот же метод  
**Then** провайдер не вызывается, hold не создаётся, статус отказа — недостаток средств, usage со списанием отсутствует
